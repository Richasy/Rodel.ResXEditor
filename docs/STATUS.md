## 实际验证（2026-10-09）

1. `npm run check`：TypeScript 严格类型检查。
2. `npm test`：9 个核心测试，XML 原文/CDATA/实体/改名/增删/只读/异常、语言布局/映射隔离、创建边界、占位符保护、Designer 标识符/保留成员校验。
3. `npm run test:host`：实际本机 VS Code 1.141.0，独立 profile/测试工作区。验证激活、语言发现、Sprout 显式默认值、脏文档、过时编辑拒绝、撤销/重做、UTF-8 BOM/CRLF 的字节级保存、UTF-16 LE BOM、外部文件重载、跨语言原子修改、Excel 往返与差异/公式拒绝、多个 Webview 共用文档、实际脚本渲染回执、原生文本 diff、外部变更不覆盖脏草稿。
4. `npm run test:ui`：headless Edge 渲染实际 media 脚本，测试 Tab、搜索/筛选、草稿同步保护、只读、差异选择、批量输入；深色/浅色/高对比度/自定义主题截图人工检查。截图在本地 `test-results/`。
5. `npm audit`：0 个已知依赖漏洞；ExcelJS 的 uuid 使用已修复版本覆盖。
6. `npm run test:designer`：生成的 C# 使用真实 .NET SDK 编译，启用 Nullable 和 TreatWarningsAsErrors。
7. VSIX 已安装到本机默认 VS Code profile；使用安装后的扩展目录作为开发路径重复宿主测试，验证安装包没有缺失依赖或 Webview 资源。

加载问题已修复：CustomTextEditor 初始化不再等待尚未挂载的 Webview 接收 postMessage，编辑器先返回，脚本 ready 后异步读取数据。宿主测试现在等待实际 Webview 渲染回执，防止空白/一直加载仅靠文档层测试漏掉。

## 当前限制与后续工作

- **真实 Copilot 联调尚未完成**：自动测试未消费用户 Copilot 配额；需在已登录 Copilot 的普通窗口主动试译样本，核对授权、模型拒绝/限额与真实模型输出。基础占位符校验已测。
- **Designer 仍需实际程序集资源读取联调**：生成代码已通过真实 C# 编译；当前显式字符串模式，无 csproj 写回、自动 on-save 生成或非 ASCII 键映射。
- XML 只处理安全的字符串数据节点。DTD、自定义实体、复杂/嵌套 value、重复 value、非文本类型不自动修复或改写；XML 中修复后继续编辑。`<root/>` 需在原文展开为 `<root></root>`。
- 保存使用原生编码；未知/旧代码页依赖用户正确设置 VS Code 文件编码，未声称所有编码都经过验证。
- 跨文档编辑原子，但磁盘保存不是多文件事务。Save all 在已识别的磁盘冲突时拒绝写入，最终比较/覆盖通过原生 XML 编辑器完成，确认对话框需人工试验。
- `.resw` 使用 `Strings/<language>/<name>.resw` 约定；不推断其他目录命名。`.resx` 的文化后缀使用 BCP-47 语法，带语言形状后缀的基础文件名可能存在歧义，需要调整命名。
- Comment 列与 Excel Comment 对应源语言。各目标文件原有注释保留，目标语言注释单独编辑目前使用单语言 XML/切换源语言。
- 当前表格完整渲染，尚未做数万行虚拟化与屏幕阅读器人工验收。无任意自定义布局适配配置、工作区所有资源映射树或 csproj 自动改写。
- VS Code 注册为可选编辑器，避免抢占 Git 比较。用户可自行选择默认；旧版本 VS Code 的用户默认关联与 Git 差异行为需要进一步矩阵测试。
- 仅支持文件系统工作区，暂不承诺虚拟工作区/web extension。未发布 Marketplace。
